# DevLog Day 1 — 족보 판정 엔진 & 이펙트 하이라이트

- 작성일: 2026-05-24
- 대상 스크립트: `Scripts/Game/GameFlow.cs`, `Scripts/Game/CardValue.cs`

---

## 1. 기능 의도

- 야추(주사위 포커)를 **카드 배틀**로 재해석 — 슬롯 5칸에 놓인 카드의 숫자 조합으로 점수 산출
- 점수 = 전투 데미지. 따라서 "지금 내 패의 최고 조합이 무엇인지"를 **실시간으로 시각화**할 필요
- 조커 카드(와일드)·체인 잠금 카드 등 변수까지 포함한 **최적 점수 자동 계산** 목표
- 플레이어가 어떤 카드를 넣어야 점수가 오르는지 직관적으로 알 수 있는 **추천(Best Pick) UX** 제공

---

## 2. 진행 — 핸드 평가 엔진

- `EvaluateHand(dice)` : 우선순위 기반 단일 판정 함수로 일원화
  - 파이브카드 → 포카드 → 풀하우스 → 스트레이트(하이/로우) → 스몰스트레이트 → 트리플 → 투페어 → 원페어 → 하이카드 순으로 하향 탐색
  - 같은 족보 내 우열은 소수점 가중치로 표현 (예: 포카드 = `80 + fourVal×1 + kicker×0.1`)
  - 동점 상황 최소화를 위해 키커(kicker)까지 점수에 반영
- 족보별 기준 점수 확정
  - 파이브카드 95 / 포카드 80 / 풀하우스 65 / 스트레이트(하이) 70 / 스트레이트(로우) 65 / 스몰스트레이트 56+ / 트리플 40 / 투페어 25 / 원페어 10 / 하이카드 가중합

---

## 3. 진행 — 조커 최적 해석

- `ResolveJokersOptimal(values, jokerFlags)` 구현
  - 조커가 N장이면 1~6 전 조합(6^N)을 **완전 탐색**, 최고 점수가 나오는 값으로 확정
  - 표시 단계와 판정 단계가 동일 함수를 쓰도록 하여 **"보이는 것 = 실제 점수"** 일치 보장
- 조커 5장 특수 콤보(잭팟) 분리 처리
  - 5장 전부 조커 → 콤보명 `???`, 점수는 `jokerJackpotMin~Max` 범위 랜덤 추첨
  - 필드(첫 슬롯) 키로 점수 **캐시** → 매 프레임 호출돼도 값이 흔들리지 않음, 조건 해제 시 캐시 비워 재추첨

---

## 4. 진행 — 이펙트 하이라이트 시스템

- 런타임 생성 `SpriteRenderer` 오브젝트 풀로 3종 이펙트 운용
  - **호버/홀드**(`effectHover`) : 덱에서 집고 있는 카드 강조
  - **조합 기여**(`effectContribute`) : 현재 최고 조합을 이루는 슬롯 카드 표시
  - **베스트 픽**(`effectBestPick`) : 슬롯에 넣으면 최고점이 되는 덱 카드 추천
- `AttachEffect()` : 카드 스프라이트 실제 바운드·lossyScale를 역산해 **테두리 크기 정밀 정합**
  - 카드가 반투명(드래프트 비행 중)이면 이펙트 알파도 동기화
- 매 프레임 `FindContributingIndices()`로 기여 슬롯 마킹 — 족보별 기여 카드 규칙 개별 구현(풀하우스 트리플+페어, 투페어 두 쌍 등)

---

## 5. 예외 처리 / 디테일

- 플레이어 턴이 아니거나 턴 전환 연출 중이면 `DetachAllEffects()`로 전부 숨김
- 체인 잠금(`IsChainLocked`) 슬롯은 점수 계산에서 제외
- 호버 중인 카드는 베스트픽과 중복 표시되지 않도록 제외
- 디버그: 최고 조합이 바뀌는 순간에만 `[GameFlow]` 로그 출력 (스팸 방지)
